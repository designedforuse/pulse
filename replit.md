# Pulse

## Overview
Pulse is a mobile sports schedule application built with Expo (React Native). Its primary purpose is to provide users with an organized view of sports events, allowing them to browse by curated viewing modes (e.g., Weekend Nights), track live events, and easily launch corresponding streaming provider applications to watch games. The project aims to offer a comprehensive, user-friendly platform for sports enthusiasts to manage their viewing schedules across various sports and providers.

## System Architecture
The application features a frontend built with Expo Router for file-based navigation in React Native. A lightweight Express.js backend serves both a landing page and the core API. Event data is primarily sourced via an API-first approach, which auto-generates schedules from various sports leagues. A local JSON file (`data/masterGuide.json`) serves as a fallback for static data. User preferences are persisted using AsyncStorage. State management for events is handled by an `EventsProvider` utilizing React Context and React Query to fetch and merge API-sourced events with local data.

**Key Architectural Decisions & Features:**
- **Navigation:** A 3-tab interface (Watch, Rituals, Explore) with Watch as the default tab.
- **Watch Tab (4-Game Chaos Setup):** Displays a multiview module prioritizing live events and anchor teams with dynamic promotion for Slot 4 based on real-time activity signals (e.g., goals, overtime, Safety Car, Red Flag, final laps). F1 Race and Sprint sessions are Chaos Mode eligible with session-based scoring (Race +80, Sprint +40, Qualifying +15); Practice sessions remain in Live Now only.
- **Ritual Featured Override:** Users can manually override the featured game on Ritual Detail pages.
- **Ritual Session Display:** Session-type events (F1 races, SVNS rugby days) display as clean tournament/session names with flag emojis instead of the team matchup format.
- **Event Presentation:** Users select viewing modes, displaying sport packs with filtered event lists. Event cards launch streaming applications.
- **Game State Normalization:** A helper consistently categorizes events as FINAL, LIVE, or UPCOMING.
- **Unified Event Card:** All event cards use a single component for consistent design, featuring sport-colored accents, team matchups, and provider details.
- **Live Event Tracking:** Real-time detection of live and upcoming events with automatic and manual refresh.
- **Favorites Management:** Users can toggle favorite teams and disable entire sports, influencing event prioritization and filtering.
- **Team Logos:** Team logos are displayed on event cards, with fallbacks.
- **UI/UX Design:** A Google-app-inspired dark theme with charcoal background, card surfaces, green accents, sport-specific colors, and the Inter font. iOS utilizes native liquid glass tabs.
- **Event Data Processing:** Node.js scripts fetch, merge, and update schedules from various sports APIs.
- **F1 Racing Integration:** Formula 1 events are fetched from ESPN, with specific card layouts and live score features.
- **Athletics (Marathon) Integration:** World Marathon Majors events display with 🏃 emoji + marathon name card layout in deep orange (#FF5722), sourced from a hardcoded schedule in `scripts/updateMarathon.ts`. Retention window: 14 days past, 120 days future.
- **Athletics (Golden Trail) Integration:** Golden Trail World Series events display with 🏃 emoji + race name card layout, league chip shows "Golden Trail" (shortened from "Golden Trail World Series"). Sourced from a hardcoded 2026 schedule in `scripts/updateGoldenTrail.ts` covering 7 regular races + Grand Finale across 8 countries on 3 continents: Zegama-Aizkorri (Spain, May 17), Ledro Sky Trentino (Italy, May 24), Quebec Mega Trail (Canada, Jul 5), Pitz Alpine Glacier Trail (Austria, Aug 1), Sierre-Zinal (Switzerland, Aug 8), Myoko Trail (Japan, Sep 20), Jinshanling Great Wall Trail Race (China, Sep 27), Muju Trail Grand Finale (South Korea, Oct 24–25). All races broadcast on FloSports (`providerId: "flosports"`, `providerReason: "gtws-flosports"`). Retention window: 14 days past, 200 days future. Merge step drops cached GTWS events not in the fresh schedule so removed/renamed races don't linger.
- **Cycling (Epic Series) Integration:** Epic Series global mountain-bike stage-race circuit displayed under sport `cycling`, league `Epic Series` (`leagueKey: epic-series`), sourced from a hardcoded 2026 schedule in `scripts/updateEpicSeries.ts`. 5 races across 4 countries: Absa Cape Epic (Mar 15–22, South Africa), 4Islands Epic (Apr 14–18, Croatia), Andorra Epic Pyrenees (Jul 2–5, Andorra), Swiss Epic (Aug 19–23, Switzerland), FNB Wines2Whales (Nov 6–15, South Africa). Each race is a single multi-day event (`eventType: "session"`, `tournamentName` = race name). All races broadcast on FloSports (`providerId: "flosports"`, `providerReason: "flosports-broadcast"`). Retention window: 14 days past, 300 days future. Surfaced in the "Cycling Morning" viewing mode alongside Grand Tours.
- **Athletics (Diamond League) Integration:** 2026 Wanda Diamond League events display with 🏃 emoji + "Diamond League — City" card layout on FloSports, sourced from a hardcoded schedule in `scripts/updateDiamondLeague.ts`. 16 events: 14 qualifying meets (Doha, Shanghai, Xiamen, Rabat, Rome, Stockholm, Oslo, Paris, Eugene, Monaco, London, Lausanne, Silesia, Zurich) + 2-day Brussels Final (Sep 4–5). Retention window: 14 days past, 160 days future.
- **Live Scores:** Real-time score updates for in-progress games, with sport-specific displays (e.g., tennis scoreboard, cricket live detail).
- **NHL Playoff Series Status:** Event cards for NHL playoff games show a small series-status row above the team matchup (e.g., "GAME 5 · DET leads 3–1", "GAME 4 · Series tied 2–2", "GAME 6 · CAR wins 4–1"). Backend fetches NHL `/v1/score/{date}` for today + next 6 days in parallel, extracts `seriesStatus` (gameNumberOfSeries, top/bottom seed wins, neededToWin), and returns alongside live scores via `/api/scores` (new `seriesStatuses` map keyed by event ID). Surfaced through `getSeriesStatus(eventId)` on the scores context. Rendered both in `UnifiedEventCard` (regular team layout) and the `ChaosCard` primary/hero card in `app/(tabs)/watch.tsx` via the `formatChaosSeriesStatus` helper.
- **Explore Tab (Tonight's Story):** A hero module surfacing high-priority narrative signals as editorial summaries, personalized based on followed teams and ritual context.
- **Explore Tab (YouTube Videos):** Narrative cards automatically receive contextual YouTube videos via search with caching and trusted channel prioritization.
- **Explore Tab (Narrative System):** Displays dynamic, narrative-driven intelligence cards (e.g., Playoff Push, Player Movement, League Moment, Momentum, Deadline Watch, Rivalry Game, Upset Alert, Clinch Watch) based on triggered data thresholds and configured logic.
- **NHL Affiliates Page (Hockey Family Tree):** Standalone reference screen at `app/affiliates.tsx` showing all 32 NHL clubs with their AHL development partner and ECHL affiliate(s). NHL-anchored card layout, hockey-blue accent. Data lives in `data/nhlAffiliations.ts` (`NHL_AFFILIATIONS` + `NHL_AFFILIATIONS_LAST_VERIFIED`); update yearly when affiliations shift. Entry point is a "Hockey Family Tree" tile on the Stories tab (between the schedule snapshot and the narrative cards). Logos resolved via `getTeamLogoUrl(team, league)` — works for NHL (ESPN CDN), AHL (theahl.com), and ECHL (HockeyTech). Route registered in `app/_layout.tsx`.
- **SVNS Live Match Tracking:** SVNS session cards display the current/next match from the World Rugby API (`api.wr-rims-prod.pulselive.com`), showing team abbreviations, scores, phase, and gender label. Data is fetched via `/api/svns-matches?city=X` with 60s server-side caching and 45s client polling. Event IDs for all 9 SVNS stops are mapped in `server/svnsMatches.ts`.
- **Automatic Schedule Refresh:** The server uses `node-cron` to automatically refresh all schedule data twice daily (6:00 AM and 6:00 PM). A manual refresh button is available in the Settings tab. Status available via `/api/refresh-status`.
- **API Endpoints:** The Express server provides endpoints for event data, live scores, narrative cards, SVNS match schedules, and debug information.

## External Dependencies
- **Expo (React Native):** Frontend framework.
- **Express.js:** Backend server.
- **React Query:** Data fetching and caching.
- **AsyncStorage:** Persistent storage.
- **NHL Public API (api-web.nhle.com):** NHL schedule data.
- **HockeyTech API (lscluster.hockeytech.com):** AHL and ECHL schedule data. Both leagues use authoritative-feed pruning: when the upstream feed returns games, any cached event in its coverage window (AHL -7/+21 days, ECHL -14/+21 days) that's missing from the fresh feed is removed (e.g. "if necessary" Game 3s in best-of-3 series that ended 2-0 are dropped). Empty fresh feed → skip pruning so a temporary upstream hiccup doesn't wipe the cache.
- **API-Hockey (api-sports.io):** ECHL schedule data (preferred source; falls back to HockeyTech web when blocked by free-plan limits). ECHL coverage is league-wide (all 16+ active teams) — no team-specific filter is applied at fetch time.
- **Odds API (api.the-odds-api.com):** SHL (Swedish Hockey League) schedule data via `icehockey_sweden_hockey_league`; upcoming events + 3-day scores; all games on FloSports. 14 teams: Brynäs IF, Frölunda HC, Färjestad BK, HV71, Leksands IF, Linköping HC, Luleå HF, Malmö Redhawks, MoDo Hockey, Rögle BK, Skellefteå AIK, Timrå IK, Växjö Lakers, Örebro HK. Retention: 14 days past, 21 days future.
- **College Hockey News (collegehockeynews.com):** NCAA BU Hockey schedule data (scraped).
- **rugbyfixture.io (iCal feeds):** URC, Top 14, English Premiership, European Champions Cup, and EPCR Challenge Cup Rugby schedules. Challenge Cup events use `rugby-challengecup-` prefix, route to FloSports, 14d past / 21d future retention.
- **fixturedownload.com (iCal feeds):** Super Rugby Pacific (schedule only) and EPL schedules. (MLS migrated off this source — fixturedownload's iCal had wrong UTC kickoff times for several CF Montréal/Toronto FC home games.)
- **ESPN API (site.api.espn.com):** MLS schedule data via `soccer/usa.1/scoreboard`. Replaces the prior fixturedownload iCal source which had wrong kickoff times for several Canadian-venue games. Daily fetch loop covers -14/+21 day window. All games route to Apple TV (`providerId: 'appletv', providerReason: 'mls-appletv'`). The merge replaces the entire in-window cache with each fetch since ESPN is authoritative.
- **ESPN API (site.api.espn.com):** Champions League (uefa.champions), Europa League (uefa.europa), and CAF Champions League (caf.champions) schedule data. CAF CL broadcasts on beIN Sports via YouTube TV; Mamelodi Sundowns is a tracked favorite. Retention: 60 days past, 90 days future.
- **ESPN API (site.api.espn.com):** NBA basketball schedule and live score data.
- **ESPN API (site.api.espn.com):** USL, FA Cup, ATP Tennis, and F1 Racing schedule data.
- **all.rugby:** Japan League One Rugby schedule data (scraped).
- **MLR (hardcoded):** Major League Rugby schedule data.
- **Golf Majors (hardcoded):** Players Championship, The Masters, PGA Championship, US Open, British Open schedule data.
- **World Marathon Majors (hardcoded):** Tokyo, Boston, London, Sydney, Berlin, Chicago, and New York City marathons as athletics/session events on FloSports.
- **ESPN API (site.api.espn.com):** International Soccer — FIFA World Cup 2026 (`soccer/fifa.world`, 104 events, FOX/FS1 on YouTube TV) and International Friendlies (`soccer/fifa.friendly`, filtered to events with US broadcast coverage, mapped to FOX/FS1/ESPN2/TNT). Retention: 14 days past, World Cup through Aug 2026, friendlies 60 days future.
- **CricAPI:** International and domestic Cricket fixtures and live scores. Uses `/v1/cricScore` (free tier, no credits needed) for live match detection, and `/v1/matches` (paginated, MAX_PAGES=10, ~20 hits/day) for schedule. Budget: 20 hits/day schedule + max 72 hits/day live (20 min TTL) = ~92/day max vs 100/day limit. Cache timestamp always updated after each API call (even when no matches found) to prevent hammering. Each cricket event stores `cricketMatchId` (CricAPI UUID) for reliable ID-based score matching. The `currentMatches` endpoint was replaced because it requires credits (account has 0 credits).
- **IPL Official Feed (scores.iplt20.com + ipl-stats-sports-mechanic.s3.ap-south-1.amazonaws.com):** IPL live scores pulled from the official iplt20.com data feed. `competition.js` returns the current season's CompetitionID (IPL 2026 = 284, fetched with `live: 1` flag, cached 24h). Schedule feed (`{feedsource}/{CID}-matchschedule.js`) polled every 60s for live `FirstBattingSummary`/`SecondBattingSummary` innings scores. No rate limits. IPL events (id prefix `cricket-ipl-`) route to this fetcher; other cricket uses CricAPI. IPL team logos use `documents.iplt20.com` outline PNG URLs per team (all 10 teams mapped in `utils/teamLogos.ts`).
- **World Rugby API (api.wr-rims-prod.pulselive.com):** Pulselive feed used for SVNS match schedules and live scores plus real-time game clock data for all major club & international rugby comps. Event IDs in `server/liveScores.ts → PULSELIVE_RUGBY_EVENT_IDS`: Super Rugby Pacific 2026, URC 2026, Top 14 2026, English Premiership 2026, Investec Champions Cup 2026, EPCR Challenge Cup 2026, MLR 2026, 2026 Six Nations. Schedule per event cached 60s; status codes (L1/LHT/L2/L3/L4/C) map to H1/HT/H2/ET1/ET2/FT and `clock.secs` provides the live minute. Pulselive results take precedence over ESPN's rugby scoreboard for any matched event.
- **MLR Official (majorleague.rugby Next.js data API):** Used for MLR live scores because Pulselive's MLR feed lags badly (matches often remain "U"/0-0 even an hour into kickoff). `server/liveScores.ts → fetchMlrOfficialScores` scrapes the homepage for the Next.js `buildId` (cached 6h) and current-week match slugs (cached 60s), then fetches `/_next/data/{buildId}/matches/{slug}.json` per matched event (cached 30s). Returns real-time `homeScore`, `awayScore`, period (FirstHalf/HalfTime/SecondHalf/PostMatch → H1/HT/H2/FT), and `gameTime` minute. Takes precedence over Pulselive for any MLR event.
