3. Scoring dimensions — exact breakdown
There are two separate scoring systems depending on sport:

A. chaosSort() — universal ranking for all sports (chaos-setup.ts:335)
This is the primary sort applied to all 4 selected slots. It is a cascading tiebreaker (not additive):

1. Live vs not live       — live wins unconditionally
2. Hockey Chaos Score     — if both are hockey + live: compare hockeyChaosScore.total
   2a. If only one is hockey+live, hockey beats all non-hockey (unconditional)
3. Racing Chaos Score     — if both racing+live: compare racingChaosScore.total
   3a. Racing with score ≥40 beats non-hockey, non-racing
4. emotionRank            — 3 (favorite team) > 2 (favorite league) > 1 (FOCUS_SPORTS) > 0
5. Ritual mode branch:
   - IN RITUAL:  sportPriority first, then tensionRank
   - NOT RITUAL: tensionRank first, then sportPriority
6. startTime              — earlier start wins
7. event.id               — lexicographic tiebreak
emotionRank values (getEmotionRank(), chaos-setup.ts:20):

3 = favorite team involved (favoriteInvolved())
2 = any team in a league the user has favorited
1 = sport is in FOCUS_SPORTS set
0 = anything else
tensionRank values (getTensionRank(), chaos-setup.ts:36):

Hockey/Soccer: diff≤1 → 3, diff≤2 → 2, else → 1
Rugby:         diff≤7 → 3, diff≤14 → 2, else → 1
Racing:        race → 3, sprint/qualifying → 2, else → 1
Cricket:       always 1
+OT/SO boost:  min(rank + 2, 5)
Non-live:      always 0
B. computeHockeyChaosScore() — hockey-only additive score (chaos-score.ts:153)
Only computed for hockey events that are currently live. Component breakdown:

statusScore       // STATUS_WEIGHTS lookup
  SHOOTOUT → 80
  OT       → 70
  LIVE     → 50
  INTERMISSION → 45
closenessScore    // score differential
  diff=0 → 25
  diff=1 → 20
  diff=2 → 10
  diff>2 → 0
timePressure      // 0–25
  OT/SO: 25
  Intermission: 5–15 proportional to period
  Regulation: proportional to minutes remaining (max 25 in final minute)
situationBoosts   // additive, can stack
  power play goal/shorthanded goal: +15
  penalty shot goal:               +25
  final 2min, one-goal game:       +25
  goal scored in last 2 min:       +18
  goalie pulled:                   +30
favoritesBoost    // capped at 10
  favorite team involved: +8 (raw), min(8, 10) = 8
momentum          // 0–10
  shots-on-goal differential × 2, capped at 10
TOTAL = sum of all components (no cap)
C. computeRacingChaosScore() — F1/racing additive score (chaos-setup.ts:110)
Only computed for racing events that are live. F1 Practice sessions are not eligible:

sessionScore      // F1_SESSION_PRIORITY lookup
  race:             80
  sprint:           40
  qualifying:       15
  sprint qualifying: 10
  sprint shootout:  10
  practice:          0 (blocked — returns total=0)
situationBoosts
  Red Flag:         +25
  Safety Car / SC:  +15
  VSC:              +10
  final laps (≥85% complete): +20
  late race (≥65% complete):  +10
favoritesBoost
  favorite involved: +8
TOTAL = sessionScore + situationBoosts + favoritesBoost

4. How favorite teams affect ranking
Favorites are consumed in three separate layers:

Layer 1 — emotionRank = 3 (universal, all sports):

// chaos-setup.ts:20–33
export function getEmotionRank(event: SportEvent, favorites: Favorites): number {
  if (favoriteInvolved(event, favorites)) return 3;  // highest priority
  const league = event.league.toLowerCase();
  // if user has ANY team in this league → emotionRank 2
  if (favLeagues.has(league)) return 2;
  if (FOCUS_SPORTS.has(event.sport)) return 1;
  return 0;
}
Layer 2 — favoritesBoost (hockey and racing scoring):

// chaos-score.ts:131–136, chaos-setup.ts:152–156
if (favoriteInvolved(event, favorites)) return { value: 8 };  // added to total score
Layer 3 — guaranteed slot (selection pass, chaos-setup.ts:487–495):

// If no anchors and no favorites yet selected, force a favorite in:
const hasAnchorsOrFavs = selected.some((c) => c.isFavorite);
if (!hasAnchorsOrFavs) {
  const favCandidate = nonAnchors.find((c) => c.isFavorite);
  if (favCandidate) { selected.push(favCandidate); }
}
Layer 4 — backfill sort (fallback to upcoming events):

// Favorite upcoming events sort before non-favorites in backfill
const aFav = a.isFavorite ? 0 : 1;
const bFav = b.isFavorite ? 0 : 1;
if (aFav !== bFav) return aFav - bFav;
favoriteInvolved() (utils/favorites.ts) checks both awayTeam and homeTeam against the user's active favorites object using case-insensitive string matching.

5. How anchor teams affect ranking
Anchor teams are hardcoded in chaos-setup.ts:183–191 and cannot be changed by the user:

const ANCHOR_TEAMS = [
  { team: "anaheim ducks", sport: "hockey", league: "NHL" },
  { team: "san diego gulls", sport: "hockey", league: "AHL" },
];
const ANCHOR_ALIASES: Record<string, string[]> = {
  "anaheim ducks": ["ducks", "anaheim"],
  "san diego gulls": ["gulls", "sd gulls"],
};
Matching — isAnchorTeam() normalizes to lowercase, checks exact match and substring match on both homeTeam and awayTeam, plus all aliases.

Selection behavior:

// chaos-setup.ts:476–481
const anchors = selectionPool.filter((c) => c.isAnchor).sort(anchorSort);
for (const anchor of anchors) {
  if (selected.length >= 4) break;
  selected.push(anchor);       // anchors fill first, before anyone else
  usedIds.add(anchor.event.id);
}
anchorSort() sorts anchors by: live first, then earliest start time. Anchors are placed into slots before any chaosSort pass runs for the general pool.

In selfHealChaosSetup(), anchors again get placement priority in replacement slots (chaos-setup.ts:693–703).

6. How sport diversity is enforced
Sport diversity is soft-enforced during the fill pass, not the anchor pass. It runs in the third selection phase only (chaos-setup.ts:498–513):

const usedSports = new Set(selected.map((c) => c.event.sport));
const remaining = nonAnchors.filter((c) => !usedIds.has(c.event.id));
while (selected.length < 4 && remaining.length > 0) {
  remaining.sort((a, b) => {
    // Events with a NEW sport sort before events of a sport already selected
    const aSportNew = usedSports.has(a.event.sport) ? 1 : 0;
    const bSportNew = usedSports.has(b.event.sport) ? 1 : 0;
    if (aSportNew !== bSportNew) return aSportNew - bSportNew;
    // Within same "new vs existing" group, fall back to chaosSort
    return chaosSort(a, b, inRitual);
  });
  const pick = remaining.shift()!;
  selected.push(pick);
  usedIds.add(pick.event.id);
  usedSports.add(pick.event.sport);  // update the used set after each pick
}
This is re-sorted every iteration, so after each pick the diversity preference adjusts. If there are fewer than 4 distinct sports available, duplicates fill the remaining slots (the fourth selection pass — lines 515–522 — has no sport filter at all).

7. How backfilling with upcoming events works
Backfill only activates when there are no live events in the candidate pool:

// chaos-setup.ts:526
if (selected.length < 4 && !hasLive) {
  const backfill = getBackfillCandidates(allEvents, favorites, now, usedIds);
  ...
}
getBackfillCandidates() (chaos-setup.ts:288) selects from today's calendar only:

Time window: now < startTime ≤ PT midnight (today's end in Pacific Time)
Already-used IDs: excluded
Sort order:
Favorites first
Then score.sportRank (lower = higher priority, from computeFeaturedScore())
Then score.ladderRank
Then earliest start time
If the pool is completely empty after all passes, getNextUpCandidate() (chaos-setup.ts:627) expands the window to tomorrow's end and returns a single event — a favorite if one exists, otherwise the earliest upcoming event.

8. Whether ritual timing, narrative/story signals, or user preferences affect Chaos Mode
Ritual timing — yes, indirectly:

isNowInAnyRitualWindow(now) is called at the top of buildChaosSetup(). If the current time falls inside any defined ritual window, inRitual = true. This swaps the sort order inside chaosSort():

if (ritualMode) {
  // sportPriority FIRST, tensionRank second
} else {
  // tensionRank FIRST, sportPriority second
}
In ritual mode, sport type wins over closeness. Outside ritual windows, closeness wins over sport type. The active ritualId is logged in the debug object but is not used for filtering — all sports remain eligible.

Narrative/story signals — no:
computeActivityScore() runs in evaluateSlot4Promotion() for Slot 4 only and detects real-time signals (goals, OT, Red Flags). It has no connection to the Stories/narratives tab content. The Stories tab generates its narrative cards independently on the server via /api/narratives — those cards are never fed back into Chaos scoring.

User preferences beyond favorites:

disabledSports — no effect on Chaos. The sport toggle in Settings is applied in watch.tsx before calling buildChaosSetup(), but only for the event lists shown in "Live Now" and "Upcoming" sections. The allEvents array passed into buildChaosSetup() comes from the full unfiltered useEvents() pool. The disabled sport filter does not strip events before Chaos selection.
favoritesOnly — no effect on Chaos. It only filters the "Live Now" and "Upcoming" flat lists below the Chaos view.
debugShowAll — no effect on Chaos.
